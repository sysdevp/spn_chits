SPN Chits – 34 Point Change Guide

Prized payment approval flow, SPN Auction, reports, cash box, accounts and HR allowances. Menu paths are from the left sidebar; URLs are relative to /admin-panel/.
Before you start
  • After a deploy, log out and log in again so the new menus are loaded.
  • New tables and columns (cash_box_entries, employee_allowances, employees.day_allowance, customer score overrides, payment desk approval columns) are created automatically the first time the page is opened. No manual SQL is needed.
  • New menus follow the existing security permissions (HR → Security Permissions).

in slab view ( account information ) > if prized red color, non prized green color fonts

9) Once prized, not shown again in the same chit

once prized no need shown in again same chit
How it works: In Prized Payment → create request, enrolments that are already prized are hidden from the customer list. The backend also blocks a duplicate prized request for the same enrolment.

20) "SPN Prized" tag everywhere

once marked as prized please show that enrollment as SPN prized tag in all areas
How it works: Wherever an enrolment / slab label is printed (slab + AR number labels, commitment enrolment names, reports, desk lists), prized enrolments get a red SPN Prized tag. Prized status is chit_details.prized_status = 1, set when Corporate Chit Admin approves a prized request.

Prized payment approval flow (points 3 – 8, 14, 28)

Request (web or customer app) → Corporate Chit Admin approves and assigns a field employee → field verification in the employee mobile app → Accounts approves and pays out → Paid.
For final / closed payments the order is: Chit Admin → Accounts payout → field verification after payout.

3) Prized allotment on the first page; submit for Corporate Chit Admin approval

prized allotment will come in 1st page itself ( submit name change as corporate chit admin approval )
Where: SPN Chit Payment → Prized Payment → New request (URL payment-priced).
How it works: Pick the customer and the allotment form (month, amount, charges, reason, remarks, documents) opens on the same page. Buttons: Save as Draft and Submit for Corporate Chit Admin Approval. Customer history is behind a "Show full customer history" toggle.

4) Corporate Chit Admin assigns a field verification member

corporate chit admin will move to field verification member set in their login approval report ( only set )
Where: SPN Chit Payment → Pending Approval → tab Chit admin.
How it works: Each row has an employee drop-down (employees of that branch) and remarks. Approve & Assign marks the enrolment prized and moves it to field verification. Reject needs remarks.

5) Field verification in the employee mobile app

field verification will done by mobile app and selected employee mobile app
How it works: The assigned employee sees the task through API mobile-field-payment-tasks (with employee_id) and submits photos + location pins through field-submit-payment-desk. On the web, the Assigned to me tab shows the same list.
Mobile app action needed: the employee app source is not in this repository. The app must call the two APIs above to list and submit field verifications.

6, 7) Accounts department checks, approves and pays out

once field employee completed ( payment move to account department ) / account department will check and approve and payout
Where: SPN Account Management → Payments Done → Accounts Payout Approval (URL payment-accounts-payout).
How it works: After field verification the request moves to Accounts. Enter payout mode, date, UTR / transaction number (not needed for Cash), bank and remarks, then Approve & Payout. Cash payouts are also queued in Cash Box Approvals (point 30).

8) Final and closed payments – same flow, field verification after payout

for final and close, same as above ( after payout then only field verification )
Where: SPN Chit Payment → Final Closed Payment.
How it works: Chit Admin approves and assigns the employee → Accounts pays out → then the field employee verifies.

14) Customer app payment requests now show in the web app

payment request by customer app is not showing in web app please check
Cause: there was no backend endpoint for customer-app payment requests.
Fix: new public API customer-payment-request. Tenant, branch and customer are filled from the enrolment, the request is marked From customer app and goes straight to Corporate Chit Admin. The Pending Approval page has a "From customer app" counter.
Customer app action needed: the customer app must post to customer-payment-request (or store-payment-desk with source=customer_app).

28) Payments done shown in SPN Account Management

Payments is done shown in SPN Account management ( final payment, prized payment, refund payment )
Where: SPN Account Management → Payments Done: Prized Payment, Final Payment, Refund Payment, Accounts Payout Approval. "Priced" is renamed to "Prized" in the menu.

SPN Auction (points 11, 12, 13, 21, 22)

11) SPN Auction main menu

SPN Auction ( main menu ) -> prized show group, prized show report
Where: New left-menu section SPN Auction: Prized Show Group, Prized Show Report, Auction Report (Scheme-wise). These links were moved out of SPN Chit Payment.

12) Prized Show Group – due number fixed

admin-panel/prized-show-group ( due no not showing )
How it works: The member list now shows the running Due No (latest installment whose auction date is today or earlier) and the SPN Prized tag.

13, 21) Prized Show Report – more details, month-wise view

prized-show-report need more details / action group of month show -> customer prized month wise view
Where: SPN Auction → Prized Show Report.
How it works: Filters for group and month number, three views (Groups, Month-wise, Table), six KPI cards (including paid out and months still to prize). Each row shows auction date, customer code, mobile, branch, due no, joined date, amount the customer paid, payout status / mode / date and who marked it. CSV export.

22) Auction report – scheme-wise, by month or auction date; branch dashboard

auction show report -> month and auction date they will see scheme wise reports ( who all are prized and prized amount ) ( dashboard also in branch level logins )
Where: SPN Auction → Auction Report (Scheme-wise) (URL spn-auction-report).
How it works: Filter by branch, scheme, month or a single auction date. Shows who is prized, prized amount, paid out and yet to pay, with scheme-wise and month-wise bars. Branch logins see only their branch.
Dashboard: every dashboard (including branch logins) shows an SPN Auction · this month strip with prized count, amount, paid out and top schemes. Click it to open the report.

Reports (points 10, 15, 18, 19, 24)

10) Completed – payment not given

once the due is completed and full due amount is collected ( if the payment is not given, please give one report ) … ( branch, scheme filter )
Where: SPN Chit Payment → Completed – Payment Not Given (URL completed-not-paid-report).
How it works: Lists enrolments where receipts cover every installment but no payout has been made. Columns: total the customer paid, last month's due, amount we give (chit value), difference (we give − customer paid), given so far, pending payout, days waiting and the payout request status. Filters: branch, scheme, search, "include already paid". KPI cards and CSV export.

15) Group View – month and year filter

group view please add month and year filter
Where: SPN Group View.
How it works: New Month and Year filters (by the date the group was formed).

18) Final closed report and promised report are separate

final closed report and promised report both are different please show in 2 reports
Where: SPN Chit Payment → Promised Report (Calendar) (URL commitment-promise-report) and Final Closed Report (URL final-closed-report).

19) Calendar view of the promised report

calendar view wise promised reports ( show in calendar there showing all details )
How it works: Both reports open in Calendar view. Each day shows the customers due that day (green = paid, red = not paid). Click a day to see the full details below it. A Table view is also available. KPIs: count, scheme value, due, collected, paid / not paid. Excel export.

24) Old reports in the new design

some reports are showing old looks please change as new design
How it works: A global theme now gives every legacy report page the new look: a green hero header, filter panel, rounded tables and highlighted totals rows. New pages built in this batch use the SPN report design (hero, KPI tiles, bars).

Customer profile and enrolment (points 16, 17)

16) Customer score edit (admin only, with remarks)

customer score edit option in customer profile ( only in admin ) ( remarks )
Where: Customer profile → score card → pencil icon (visible only for admin logins).
How it works: Enter a score (0–1000) and the remarks (required), then save. A "Manual" badge shows and every change is logged with who changed it. "Reset to system score" removes the override. The Customer Category report also uses the manual score.

17) Due date filled automatically from the date of joining

date of joining, due date will automatically come 1st due completion date
Where: New SPN / commitment enrolment form.
How it works: Choosing the Date Of Joining fills the Due Date (1st due completion date) with the same date. It can still be changed manually.

Accounts, cash box, income and expenses (points 23, 25, 30, 33, 34)

23) Petty cash branch report (new design)

in accounts menu ( petty cash creations for branch report, ( new look design in all pages )
Where: SPN Account Management → Branch Reports → Petty Cash Branch Report.
How it works: Branch-wise petty cash income, expense and balance, expense heads as bars (click a head to filter), and every entry. Filters: branch, date range, income/expense. CSV.

25) Branch-wise income & expenses with AI insights

branch wise income and expenses in same report and using AI please give proper reports
Where: SPN Account Management → Branch Reports → Branch Income & Expense (AI).
How it works: For each branch: income (collections, RF, other charges, petty income, approved my-cash) and expenses (petty expenses, prized / final / refund payouts, allowances). Shows net, expense % of income, change vs the previous period of the same length, and the top expense head, with a details drill-down. AI insights are generated automatically, for example: the top branch, branches spending more than they earn, high expense ratio, income drops or growth over 15%, expense jumps over 25%, and the company average per day.

30) My Cash Box with admin approvals

my cash box -> reports, payout all are approvals from here ( admin will approve ) then only move the amount in cash box, if the cash is collected in receipt it will added in cash box
Where: SPN Account Management → My Cash Box → My Cash Box and Cash Box Approvals.
How it works:
  • Receipt collections (and RF, other charges, petty income) are added to the cash box automatically.
  • Payouts approved by Accounts, and any manual + Cash entry (cash in / out), go to Cash Box Approvals first. They change the cash box balance only after an admin approves them.
  • Each approval shows who requested it and who approved / rejected it, with time and remarks. Rejecting needs remarks.

33) Income cash box – collection cash, RF cash, my cash

income cash box ( collection cash, rf cash, my cash ) box, need separate wise report in single page and filters
Where: My Cash Box → Income Cash Box Report.
How it works: Separate boxes for Collection cash, RF cash, My cash and Other (cash and bank amounts shown). A day-wise table shows each box, total income, out and running balance. Filters: branch, date range, Cash / Bank. Click a box to filter the ledger. CSV.

34) My Day report

my day report ( client will design this report ) ( expenses and income ) ( cash or bank ) ( branch )
Where: My Cash Box → My Day Report.
How it works: For one day and branch: income heads and expense heads, each split into Cash and Bank, with net cash in hand and net bank. All entries of the day are listed below. Prev / Next day buttons, Print and CSV. The layout is ready to be adjusted to the client's design.

Top bar, notifications, approvals (points 26, 27, 29)

26) Top bar cleaned up

top bar no need menus ( subscriber, collection, payments .. etc no need ) please give the proper remaining items in alignment
How it works: The Subscriber / Collection / Payment / Accounts drop-downs were removed. The top bar is now: menu button, search, and on the right side the branch, date, notifications bell and profile, all aligned.

27) Notifications – tasks and today's targets

notifications ( like task and today targets ) like that
How it works: The bell shows a red count and opens a panel with:
  • Today's tasks of the logged-in employee, with overdue tasks in red.
  • Today's targets, showing achieved vs target and a progress bar.
  • Approvals & requests: payments waiting for Chit Admin, field verification or Accounts; field verifications assigned to you; cash box entries to approve; leave requests; and open office tickets.
Each item opens the related page. The panel refreshes every 2 minutes.

29) Who requested and who approved – in approvals

approvals will design on who is requested and who is approved in all approvals
How it works: The requested-by / approved-by trail (name and time) now shows in:
  • Payment desk: prized, final and refund (chit admin, field employee and accounts are named).
  • Cash Box Approvals.
  • Leave / Permission / OD requests.
  • Refund Approval.
  • SPN Eligibility Approval (shows requested by).

HR allowances (points 31, 32)

31) Day allowance column and daily ₹200 report

in employee creation -> day allowance column please, daily 200 allowance in one report
Where: Employee create / edit form has a new Day Allowance (₹ / day) field (default 200). Report: SPN HR Department → Day Allowance (₹200/day).
How it works: Every present day in attendance earns the employee's day allowance. Use the day-wise view to select unpaid days and Mark selected as paid. The employee-wise view shows days, earned, paid and to-pay, and the rate can be edited there. Filters: branch, employee, date range. CSV.

32) Petrol allowance screen and reports

petrol allowance given like that expenses separate screen and proper reports ( month wise, day wise with employee )
Where: SPN HR Department → Petrol Allowance.
How it works: + Petrol entry: employee, date, KM × rate (or a direct amount), mode and remarks. Edit or delete entries. Reports: Day-wise, Employee-wise (days, KM, amount) and Month-wise. Paid allowances count as expenses in Branch Income & Expense and My Day.
